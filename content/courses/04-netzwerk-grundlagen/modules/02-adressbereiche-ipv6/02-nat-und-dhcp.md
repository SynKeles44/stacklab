Zu Hause hängen Laptop, Handy und Fernseher im WLAN – aber dein Internetanbieter gibt dir meist nur
**eine** öffentliche IPv4-Adresse. Trotzdem surfen alle gleichzeitig, und keiner hat je eine Adresse
eingetippt. Dahinter stecken zwei Mechanismen: NAT und DHCP.

## NAT: Adressen beim Rausgehen austauschen

Dein Router hat innen eine private Adresse (`192.168.178.1`) und außen eine öffentliche
(`203.0.113.7`). Schickt ein Gerät ein Paket ins Internet, **ersetzt der Router die private
Absender-Adresse durch seine öffentliche**. Das nennt man [[nat|NAT]] (*Network Address Translation*).

![NAT: Laptop und Handy im Heimnetz teilen sich die öffentliche Adresse des Routers](/assets/netzwerk-grundlagen/nat.svg)

Damit Antworten zurückfinden, führt der Router eine **NAT-Tabelle** und unterscheidet die Geräte über
Ports:

| Intern (privat) | Extern (öffentlich) |
|---|---|
| `192.168.178.23:50123` | `203.0.113.7:61001` |
| `192.168.178.40:42210` | `203.0.113.7:61002` |

> [!MERKSATZ]
> NAT tauscht beim Verlassen des Netzes die private Absender-Adresse gegen die öffentliche des Routers.
> Antworten finden über die NAT-Tabelle zum richtigen Gerät zurück.

## Von außen nach innen und NAT anderswo

Ungefragte Pakete von außen haben keinen Tabelleneintrag – der Router verwirft sie. Soll ein Gerät
trotzdem erreichbar sein, legst du ein [[port-forwarding|Port-Forwarding]] an, z. B. „öffentlicher
Port 8443 → `192.168.178.50:443`“.

NAT gibt es auch woanders: Internetanbieter teilen mit Carrier-Grade-NAT (`100.64.0.0/10`) eine Adresse
unter vielen Kunden auf, und in der Cloud lässt ein **NAT-Gateway** Server in privaten Subnetzen
ausgehend ins Internet, ohne dass sie von außen erreichbar werden.

> [!FEHLER]
> **„Ich habe NAT, also brauche ich keine Firewall.“** Port-Forwardings, automatische Freigaben (UPnP)
> oder IPv6 ohne NAT hebeln den Effekt aus. Schutz kommt von einer Firewall mit klaren Regeln.

## DHCP: Konfiguration automatisch

Ein Gerät braucht vier Angaben: **IP-Adresse**, **Netzmaske**, **[[default-gateway|Standard-Gateway]]**
und **DNS-Server**. [[dhcp|DHCP]] verteilt sie automatisch in vier Schritten:

| Schritt | Wer → wen | Inhalt |
|---|---|---|
| **D**iscover | Gerät → alle (Broadcast) | „Gibt es einen DHCP-Server?“ |
| **O**ffer | Server → Gerät | „Nimm 192.168.178.23, Gateway .1, DNS .1“ |
| **R**equest | Gerät → alle | „Die nehme ich.“ |
| **A**cknowledge | Server → Gerät | „Bestätigt, gültig für 10 Tage.“ |

Erkannt wird das Gerät an seiner [[mac-adresse|MAC-Adresse]], der Hardware-Adresse der Netzwerkkarte.
Die Vergabe gilt für eine *Lease*-Zeit und wird vorher verlängert.

## Gateway und Fehlersuche

Das Standard-Gateway steht als `default`-Route in der Routing-Tabelle und muss im eigenen Subnetz liegen:

```text title="ip route"
default via 192.168.178.1 dev wlan0 proto dhcp metric 600
192.168.178.0/24 dev wlan0 proto kernel scope link src 192.168.178.23
```

Jeder Schritt grenzt den Fehler ein: Keine Adresse oder eine aus `169.254.0.0/16` heißt, DHCP hat nicht
geklappt. Antwortet das Gateway nicht, liegt das Problem im lokalen Netz. Klappt ein `ping` auf eine
IP-Adresse im Internet, aber nicht auf einen Namen, ist der DNS-Server schuld.

```bash title="Terminal"
ip addr                    # Adresse da? 169.254.x.x = kein DHCP!
ip route                   # default-Route da?
ping -c 2 192.168.178.1    # antwortet das Gateway?
cat /etc/resolv.conf       # welcher DNS-Server?
```

> [!PRAXIS]
> Externe Partner, die deine Server per IP freischalten sollen, brauchen die öffentliche Adresse deines
> NAT-Gateways – nicht die privaten Server-Adressen. Viele Teams geben dem NAT-Gateway deshalb eine
> feste öffentliche Adresse.

## Zusammenfassung

- **NAT** ersetzt private Absender-Adressen durch die öffentliche Adresse des Routers; die NAT-Tabelle ordnet Antworten zu.
- Verbindungen von außen brauchen **Port-Forwarding**; NAT ist kein Ersatz für eine Firewall.
- **DHCP** verteilt Adresse, Maske, Gateway und DNS nach dem Ablauf **DORA**.
- Das **Standard-Gateway** ist die `default`-Route und liegt im eigenen Subnetz.
- Fehlersuche: `ip addr` → `ip route` → `ping` zum Gateway → `/etc/resolv.conf`.
